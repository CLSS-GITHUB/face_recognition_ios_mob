## 8.2 Naming conventions

| Concept | Convention | Example |
|---|---|---|
| File names | `snake_case.dart` | `live_enrollment_screen.dart` |
| Classes / enums | `PascalCase` | `LiveEnrollmentScreen`, `LivenessStep` |
| Constants | `lowerCamelCase` | `verificationThreshold = 0.75` |
| Riverpod providers | `<noun>Provider` | `faceRecognizerProvider` |
| Async controllers | `<Noun>Controller extends Notifier<...>` | `EnrollmentController` |
| Test files | `<source>_test.dart` mirroring `lib/` path | `services/face_matching_service_test.dart` |

## 8.3 Single source of truth: `core/constants/thresholds.dart`

Place every numeric threshold from Android in one file so behavioral parity is auditable:

```dart
class FaceThresholds {
  FaceThresholds._();

  // Embedding
  static const int inputSize = 112;
  static const int embeddingDim = 192;
  static const int tfliteThreads = 4;
  static const double pixelMean = 127.5;

  // Quality (QualityAssessor)
  static const double minBrightness = 45;
  static const double maxBrightness = 245;
  static const double centeringNormal = 0.20;
  static const double centeringTurning = 0.40;
  static const double yawLimit = 25;
  static const double pitchLimit = 25;

  // Liveness
  static const double eyeClosed = 0.25;
  static const double eyeOpen = 0.60;
  static const double yawTurn = 15;
  static const double mouthOpenEnter = 0.85;
  static const double mouthCloseExit = 0.75;
  static const double stillAngle = 5;

  // Crop & save
  static const double faceCropMargin = 0.25;
  static const int jpegQuality = 90;

  // Matching
  static const double verifyThreshold = 0.75;
  static const double reEnrollVerifyThreshold = 0.80;
  static const double duplicateFaceThreshold = 0.85;
  static const double templateDedupThreshold = 0.95;

  // Retry
  static const int extractionRetryLimit = 150;

  // Storage guards
  static const int maxTemplatesPerUser = 1000;
  static const int maxArrayLength = 10000;
}
```

A unit test (`thresholds_parity_test.dart`) should pin these values; any change forces a deliberate update.

## 8.5 What lives where, and why

- **`lib/services/`** holds infrastructure-y, single-purpose services that screens consume directly. They are *not* feature-specific — if a future "Document Verification" feature wanted face detection, it would reuse `FaceDetectionService`.
- **`lib/features/face_verification/`** holds everything that is unique to this feature: enrollment screens, the registration dialog, the user management view. The current app has only one feature; the folder makes it cheap to add a second.
- **`lib/data/database/`** is **not** under the feature because the schema may grow with cross-feature concerns; keeping it flat under `data/` mirrors `repository.fromService` patterns and keeps Drift codegen happy.
- **`lib/core/`** holds anything that doesn't depend on Flutter widgets and could in principle run in a pure-Dart unit test (no `WidgetsFlutterBinding`).

## 8.6 What `pubspec.yaml`'s `flutter` section needs

```yaml
flutter:
  uses-material-design: true
  assets:
    - assets/models/mobile_facenet.tflite
```

Optionally pre-load the model via `rootBundle.load(...)` at app start to avoid a first-frame stutter; cache the bytes in a Riverpod provider.
