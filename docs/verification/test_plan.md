# Verify Identity Flow — Detailed Test Document

**Companion to**: `docs/verification/architecture_recommendations.md` and
`docs/migration/13_test_strategy.md`.

This document is the acceptance test catalogue for the Verify Identity flow
and the Manage Users screen. Test cases are written so a manual QA engineer
can execute them on a real device, and so a Flutter test author can pick the
ones marked **(Auto)** and target them with `flutter_test` /
`integration_test` / `alchemist`.

## Conventions

- **Test Case ID** uses one of:
  - `VER-FUNC-###` – functional
  - `VER-UI-###` – UI / widget
  - `VER-CAM-###` – camera
  - `VER-RT-###` – real-time verification
  - `VER-FRD-###` – fraud / anti-spoof
  - `VER-PERF-###` – performance
  - `VER-LOW-###` – low-end device
  - `VER-OFF-###` – offline
  - `VER-EDGE-###` – edge / boundary
  - `VER-FAIL-###` – failure / retry
  - `VER-SEC-###` – security validation
  - `VER-DB-###` – database validation
  - `MGR-###` – Manage Users
- **Status** is left blank in the spec; QA fills it during a run.
- **Priority**: P0 (must pass to release), P1 (must pass for GA), P2 (nice to have).
- **Device Type**: `LowEnd` (Galaxy A21 / Redmi 9), `MidRange` (Pixel 6a / iPhone 12 mini), `HighEnd` (Pixel 8 / iPhone 15 Pro). `Any` = device-independent.
- **OS Type**: `Android 9+`, `iOS 13+`, `Both`, or specific minor (e.g. `Android 14`).
- **(Auto)** in the scenario column = candidate for automated coverage; the matching test file lives under `test/` or `integration_test/`.

Numeric thresholds quoted in expected results trace back to
`lib/core/constants/thresholds.dart`. Any change to those constants must
update both the file and this document.

## P. Sign-off criteria

A release candidate is sign-off-ready when:

1. All P0 tests in this document pass on **MidRange Android + iOS** plus
   one **LowEnd Android**.
2. All P0 tests in §K (Security) pass on a tamper-resistant build (release,
   non-debug).
3. Performance gates in §F pass on the canary device for 3 consecutive runs.
4. Threshold parity test (`thresholds_parity_test.dart`) green.
5. Cross-stack template parity test green against a fresh Android-produced
   fixture.
6. Coverage ≥ 70 % on `lib/services/`, `lib/data/`, `lib/core/utils/`,
   `lib/features/face_verification/domain/usecases/`.
7. No P0 / P1 leaks reported by `leak_tracker` in the 20-cycle stress test.
